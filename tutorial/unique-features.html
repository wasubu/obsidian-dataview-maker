Custom Database Studio injects a robust global db object into your scripts. Here is the exhaustive list of all available helper functions:

Container-Scoped DOM Selectors: `$` and `$$`

When writing scripts in traditional web development, calling document.querySelector() searches the entire webpage. In Obsidian, this is dangerous because it could accidentally modify Obsidian's own UI elements or other notes on the screen.

Custom Database Studio automatically provides scoped helper functions $ and $$ inside your script:

// Selects the first matching element INSIDE your canvas container
const button = $('#my-submit-btn');

// Selects ALL matching elements INSIDE your canvas container
const allCards = $$('.book-card');

allCards.forEach(card => {
  card.style.borderColor = 'var(--interactive-accent)';
});

This guarantees your CSS queries and DOM manipulations remain strictly isolated to your dashboard.

Reactive State Stores (`db.state`)

Building dashboards often requires UI components to update automatically whenever data changes. The db.state() helper creates a reactive state container with built-in subscription handling:

// Initialize reactive state with an initial value and change listener
const counter = db.state(0, (newValue) => {
  console.log('State changed to:', newValue);
  $('#counter-label').innerText = newValue;
});

// Get the current value
console.log(counter.val); // 0

// Set a new value (triggers the listener automatically)
counter.val = 5;

// Update using previous state
counter.update(prev => prev + 1);

Persistent Namespaced Storage (`db.storage`)

To save user settings, preferences, or local dashboard data that survives Obsidian restarts, use db.storage(). It automatically prefixes keys with your plugin's namespace (cds_[namespace]_[key]) to prevent collisions:

// Initialize namespaced storage
const store = db.storage('my_dashboard');

// Save data
store.set('theme_pref', 'dark');
store.set('favorites', [1, 4, 9]);

// Retrieve data with an optional default fallback
const theme = store.get('theme_pref', 'light');

// Remove a key or clear all namespaced keys
store.remove('theme_pref');
store.clear();

Procedural Audio Synthesis (`db.beep`)

Add rich interactive feedback to buttons, timers, or games without needing external audio files. db.beep() utilizes the browser's Web Audio API and includes bulletproof auto-closing teardown:

// Basic sine beep (Frequency 440Hz, Duration 0.1s)
db.beep(440, 0.1, 'sine', 0.1);

// Retro square wave click for buttons
db.beep(800, 0.05, 'square', 0.05);

// Low error buzz (Sawtooth wave)
db.beep(120, 0.2, 'sawtooth', 0.15);

Managed Timers & Animation Loops

Creating setInterval timers or requestAnimationFrame loops in vanilla JS often leads to memory leaks or audio bleeding when switching away from a note. Custom Database Studio manages these automatically:

// 1. Managed Interval Timer (Auto-stops on note unload)
const countdown = db.timer(1000, () => {
  console.log('Ticked every second');
});
countdown.start();

// 2. High-Performance 60FPS Animation Loop
const animator = db.loop((deltaTime, timestamp) => {
  updatePhysics(deltaTime);
  renderCanvas();
});
animator.start();

Vault Event Listeners & Teardown Hooks

You can listen to vault modifications or register custom cleanup functions that execute when your canvas view is destroyed:

// Listen for any markdown file modification in your vault
db.onVaultChange((file) => {
  console.log('Note modified:', file.path);
});

// Register custom cleanup logic (unbinding custom window listeners, sockets, etc.)
db.onCleanup(() => {
  console.log('Canvas view is being unloaded. Cleaning up...');
});
